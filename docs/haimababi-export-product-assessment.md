**海马爸比相册导出工具：移动端与桌面端方案评估**

调研日期：2026-10-24。本文结合本次实际导出和平台官方文档；标注为“待验证”的能力尚未在海马爸比上完成端到端验证。

建议先做面向 Android 手机的桌面导出助手，同时用一个短期技术验证确认 Apple Silicon Mac 能否直接运行并自动操作海马官方 iPad App。Android 独立手机版适合作为第二条产品线；iPhone 独立 App 先承担已保存照片的归档。长期争取厂家授权的相册接口，可以明显改善上手和持续同步体验。

本次未记录完整的 Android/海马 App 版本兼容矩阵，也未比较 App 下载文件与摄像头源文件的画质。商业描述宜使用“保存官方 App 提供的照片文件”，原图能力应经过源文件比对后再声明。

**通用流程需要拆开。**

一套导出产品至少包含五步：发现来源中的可用照片或日期组 → 触发官方导出或取得授权下载地址 → 等待文件落盘 → 搬运并验证 → 生成归档和完整性报告。ADB、无障碍和 macOS 辅助功能只是第一、二步的不同适配器；文件账本、恢复、去重索引和结果报告可以共用。

读取手机照片目录只解决后半段。普通系统相册权限不等于访问海马 App 内尚未导出的相册，也不等于获取海马账户中的完整照片清单。

**各路线的比较。**

优先级含义：P0 为首版主路线或立即验证的路线，P1 为后续扩展，P2 为补充/专家路线。成本为相对判断，包含上手和支持成本，不是报价。

| 路线 | 运行位置与覆盖 | 全流程能力/证据 | 用户上手 | 维护与主要限制 | 建议 |
|---|---|---|---|---|---|
| 桌面 + Android 真机，ADB/UI 自动化 | macOS、Windows；来源为 Android 手机 | macOS 本次已验证；Windows 移植与驱动待测 | 开发者选项、USB 调试、电脑授权、选目标目录 | 手机需解锁并停留在相册流程；UI 版本适配；Windows 可能需 OEM 驱动 | P0 主路线 |
| Android 独立 App，无障碍 + 目录授权 | Android 手机直接保存，之后可传电脑/NAS | 平台能力支持，海马集成待验证 | 安装、无障碍授权、导出目录授权 | 占用官方 App 前台；OEM 保活；敏感设置和商店审核 | P1 手机主路线 |
| Apple Silicon Mac 运行官方 iPad App，桌面助手自动化 | M1 及更新 Mac；账户相册可用性待测 | 海马官方商店列出 Mac 兼容；导出未实测 | 安装官方 App、在官方界面登录、给桌面助手授权 | 需验证登录、相册覆盖、控件树、下载位置 | P0 技术验证，成功后成为 Mac 主路线 |
| 浏览器 WebUSB/ADB | 支持 WebUSB 的桌面浏览器 + Android 手机 | WebUSB 能力存在，海马端到端待测 | 减少桌面安装；仍需调试授权和 USB 选择 | 浏览器兼容、USB 接口占用、文件写入授权、标签页生命周期 | P1 分发实验，复用 Android 核心 |
| 桌面 Android 模拟器运行官方 App | Windows/Mac；同账户相册是否一致待测 | 尚未验证 | 安装运行环境、在官方 App 登录 | ABI、相机 P2P/网络库、虚拟环境兼容、账户数据范围 | P2 验证，不能提前承诺覆盖 iPhone 用户 |
| 普通 iPhone App + PhotoKit/Files | iPhone 系统照片库或用户导入文件 | 能归档已由官方 App 保存的照片 | 系统照片/文件授权 | 无普通公开权限直接控制另一个 App 或读取其私有数据 | P1 归档助手，不能单独完成前半段 |
| Mac + iPhone XCTest/Appium/WDA | iPhone 真机 + Mac | 平台测试能力支持，海马集成未测 | Xcode、签名测试 runner、信任电脑、开发者模式等 | 签名与配置支持成本高；依赖测试工具链 | P2 专家模式/内部工具 |
| 厂家授权相册 API/SDK | 可共用移动端、桌面端同步核心 | 有历史官方开放平台；当前中国版相册 API 未确认 | 理想情况下由厂家提供账户委托授权 | 接口获取、授权范围、历史分页、原图与限流能力未知 | 长期优选；并行尽调 |
| 摄像头 SD 卡/厂家数据副本 | 读卡器或厂家提供文件 | SD 规格、数据副本渠道有文档；相册等价性未证实 | 读卡或等待客服处理 | 不同机型、加密/格式、照片是否在卡上、文件范围未知 | 补充入口 |

ADB 需要 USB 调试和电脑 RSA 授权；`device` 状态只说明连接到 ADB，产品仍需确认设备已可操作、屏幕状态和目标 App。Windows 的部分设备需要 OEM USB 驱动，Mac 通常不需要。Android 11+ 的配对式无线调试可作为坏线材的替代连接方式，但仍有首次配对和局域网条件。[ADB 官方说明](https://developer.android.com/tools/adb)、[OEM USB 驱动](https://developer.android.com/studio/run/oem-usb)

ADB 的文件传输走自己的协议，切换 MTP“文件传输”不是取得 ADB 授权的替代步骤。连接诊断应分别检测 USB/ADB 状态、shell 可用性和实际小文件传输，不把所有失败都归因为授权或线材。

UI Automator 官方支持跨 App 访问可见控件。产品应优先按资源 ID、文字和结构找控件，并等待状态改变；本次命令行 `uiautomator dump` 加点击适合原型，正式版本可以评估一个小型设备端 UiAutomator runner，减少 XML 往返和固定休眠，但它仍属于测试工具链，需要验证兼容性。[UI Automator](https://developer.android.com/training/testing/other-components/ui-automator)

WebUSB 要求安全上下文，并由用户手势触发设备选择。网页只是另一种承载形式，不能免除 Android 调试授权，也不能借此获得 iPhone 的 ADB 能力。[Chrome WebUSB](https://developer.chrome.com/docs/capabilities/usb)

**Android 手机端的可行产品。**

一个独立 APK 可以用 AccessibilityService 执行用户主动启动的固定导出流程，在官方 App 页面按日期勾选并下载，再用 SAF 请求用户授权具体的导出目录。若该 OEM 的文件选择器允许授权此目录，可以减少对整个照片库的访问；目录可选性、持续授权和新文件发现都应在实机上验证。另一条读取路径是 MediaStore，但要处理 Android 13+ 的图片权限，以及 Android 14 的“仅部分照片”授权。[无障碍服务](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[SAF](https://developer.android.com/training/data-storage/shared/documents-files)、[媒体文件访问](https://developer.android.com/training/data-storage/shared/media)、[Android 14 部分照片访问](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)

这条路线的核心取舍是：家长省去电脑和开发者选项，代价是授予较敏感的无障碍访问，并在导出期间保持官方 App 可交互。文件搬运可以采用长任务机制，但它不会让跨 App UI 自动化在锁屏后继续可用。[用户发起数据传输任务](https://developer.android.com/develop/background-work/background-tasks/uidt)

Google Play 当前允许用途明确、规则固定的确定性自动化；它限制可自行发起、规划和执行动作/决策的自主自动化。这个产品适合固定状态机，提交所需声明并做显著披露和积极同意；相册导出工具不应把自己声明为专为残障用户设计的 accessibility tool。中国各 OEM 商店应逐家确认分发要求，Google Play 的批准不能代表其他商店批准。官网 APK 侧载也可能遇到 Android 的“受限设置”步骤。[Play 无障碍政策](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en)、[Android 受限设置](https://support.google.com/android/answer/12623953?hl=en)

**iPhone 与 Mac 的产品边界。**

普通 iPhone App 受沙箱隔离，PhotoKit 访问的是系统照片库。用户先在海马官方 App 保存图片后，归档助手可以导入并保存到文件、电脑或 NAS；它不能仅凭照片权限读取海马私有相册。Shortcuts 也取决于海马主动提供 App Intents/快捷指令动作，当前未证实存在相册导出动作。[Apple 平台安全](https://support.apple.com/en-ca/guide/security/sec15bfe098e/web)、[PhotoKit](https://developer.apple.com/documentation/photos/phphotolibrary)、[App Intents](https://developer.apple.com/documentation/AppIntents)

一个值得优先验证的机会是：海马爸比官方 App Store 条目明确列出 macOS 11+、Apple M1+ 兼容。可以在 Apple Silicon Mac 安装官方 iPad App，用户在官方界面登录，再由桌面助手操作它。这个方案可能避开手机 USB 连接，亦可能覆盖以 iPhone 为主的家庭，但必须实测同账户照片范围、下载文件位置与辅助功能控件树，商店兼容列表本身不证明导出可用。[海马爸比官方商店条目](https://apps.apple.com/cn/app/%E6%B5%B7%E9%A9%AC%E7%88%B8%E6%AF%94/id1516955927)、[Apple Silicon Mac 运行 iPhone/iPad App](https://support.apple.com/guide/app-store/iphone-ipad-apps-mac-apple-silicon-fird2c7092da/mac)

XCTest/WDA 能操作已安装的官方 App，海马 App 本身不必重新签名，但测试 runner 要完成签名与部署。应把它视为专家工具，而不是普通 iPhone App 的运行时权限。iPhone Mirroring 可作为另一个研究项；Apple 的镜像功能并不自动提供稳定的第三方跨 App 自动化接口。[XCUIApplication](https://developer.apple.com/documentation/xcuiautomation/xcuiapplication/init%28bundleidentifier%3A%29)、[Appium 真机配置](https://appium.github.io/appium-xcuitest-driver/10.43/getting-started/device-setup/)、[iPhone Mirroring](https://support.apple.com/en-us/120421)

**直接读取数据值得研究，但现在证据不足。**

厂家曾发布 SimCam Open Platform V2.0.0，文档修订日期为 2020-06-15，列出 SimCam Baby，目标账户为 SimHome。文档主要覆盖事件推送、设备列表和隐私模式，没有列出海马爸比时光相册的分页与图片下载接口。因此可以说“有厂家开放能力的历史线索”，不能说“已有可用的海马相册 API”，也不能说“厂家完全没有 API”。[官方历史开放平台 PDF](https://www.simshine.ai/images/SimCam%20Open%20Platform-V2.0.0.pdf)

直接 API 路线一旦获得授权且能覆盖相册，优势最明显：批量清单、断点、限流和后台增量都可以实现，不用占用官方 App 页面。技术验证应检查账户域、相机域、稳定图片 ID、历史范围、分页/游标、原文件地址、时区、校验值、token 续期及撤销授权。未公开私有接口会带来签名、登录和版本变更维护，应作为独立研发项，不能把尚未观察到的接口算进首版交付。

同样不能从“视频本地存储”的宣传推出所有时光相册照片都在 SD 卡。官方服务页明确了 SD 卡规格，隐私政策又提到部分产品数据经服务器同步；具体照片来源可能与功能、机型和版本有关。读卡路线应在测试摄像头生成已知照片后，与官方 App 导出文件做尺寸、时间和哈希比对。[官方服务支持](https://www.haimababi.com/service)、[官方隐私政策](https://www.simshine.cn/hippo-baby-privacy.html)

隐私政策提供个人信息副本申请渠道，但没有承诺相册原图、已删除历史或 ZIP 格式。可以为用户生成申请模板并接收导入厂家交付文件；这不是即时自动导出的替代品。[官方数据副本条款](https://www.simshine.cn/hippo-baby-privacy.html)

**本次原型必须改进的地方。**

| 本次暴露的问题 | 产品实现要求 |
|---|---|
| ADB 输出空格被误当为制表符，连接监测曾误报 | 用协议状态或稳健的字段解析，分别报告真实断线、未授权、锁屏与解析异常；验证诊断本身 |
| 连接设备标识曾改变 | 每个任务绑定用户确认的设备；所有命令显式指定该设备；身份变化即暂停 |
| 手机休眠时读到系统锁屏/通知层 | 先确认前台包和页面；锁屏后等待用户认证；保留任务断点 |
| 日期复选框可能被底部操作栏遮挡 | 按控件几何和遮挡关系排除点击；资源 ID/语义匹配后才执行 |
| 下载与删除按钮紧邻 | 状态机仅允许明确识别的下载动作；未知结构暂停；适配器升级需做回归验证 |
| 固定时间等待和反复 XML dump 成本高 | 使用文件新增、UI 状态、下载完成事件等条件等待；批量操作后统一观测 |
| “仅未下载”属于官方 App 的状态 | 仅作为优化；真正完成以本工具账本和本地文件为准，不能只看标签 |
| 文件数量相同不能证明每张都完整 | 使用临时文件、大小、SHA-256、图片可解码性检查，成功后原子提交 |
| 历史范围短于用户使用年限 | 结果报告标出“来源当前可访问范围”和缺口；不把导出完整等同于恢复历史 |

**建议的共享核心。**

可把桌面和手机的导出能力拆成 `SourceAdapter`、`ExportSession`、`BatchQueue`、`FileTransfer`、`ArchiveLedger` 和 `CoverageReport`。UI 适配器负责官方 App 的页面和动作，传输适配器负责 ADB/SAF/MediaStore/文件导入，账本负责恢复与验证。

每个文件至少记录：来源账户/设备的本地标识、稳定照片 ID（可得时）、原始文件名、字节数、SHA-256、推断拍摄时间及其来源/时区、目标路径、处理状态和错误。图片 ID 不可得时可以用来源文件名和内容哈希作为本地索引，仍需承认无法据此证明来源端全量总数。

AI 可以用于开发时探索页面、发现版本差异和辅助生成适配规则。正式导出循环优先采用固定规则和文件状态验证，不必让大模型为每次点击规划动作。通用视觉 Agent 作为运行时主路径会增加结果不确定性、模型成本和照片画面处理范围；Android 商店分发还需遵守前述自动化边界。若采用 OCR 或视觉定位兜底，应优先在本地处理，并继续由明确的动作白名单和状态机决定是否执行。

推荐状态流为：设备与来源确认 → 支持版本和页面检查 → 枚举日期/批次 → 官方下载 → 观察落盘 → 复制临时文件 → 验证 → 原子提交 → 写账本 → 下一批。连接中断、锁屏、未知弹窗、控件变化或连续无进展时暂停，恢复后从未提交项开始。

原文件保留不变；易读日期名、按年月目录和重复内容索引可以作为归档视图。文件名推断出的时间要标明来源，不能未经核实写成真实 EXIF 拍摄时间。照片内容默认留在用户设备与目标目录，诊断只记录必要的版本、控件和计数；用户主动提交截图时提供本地遮挡选项。

任务完成报告至少区分三件事：

1. **搬运完整性**：每个已取得文件在目标位置的大小、哈希、可读性是否通过。
2. **来源覆盖**：可见/可枚举的最早与最晚日期、已处理批次、已知失败项，以及是否有可核对的来源总数。
3. **质量与历史限制**：文件来自官方 App 导出；最高原图质量是否验证；更早的缺失历史是否仍存在于其他来源。

**首版范围与验证顺序。**

建议首版定位为“本地照片归档助手”：用户打开官方相册，连接设备，选择目标目录，再启动固定导出任务。优先提供当前来源、已保存数、待重试数、当前日期、暂停/恢复、完成报告。默认保留手机上的已导出照片，归档器不负责清理来源。

| 阶段 | 交付/验证 | 继续投入的门槛 |
|---|---|---|
| 技术验证 | 将本次脚本整理为可重启的桌面核心；验证 Mac 官方 iPad App；验证 Android SAF + 无障碍最小流程 | 原始文件可取得、控件可识别、同账户相册范围可解释、失败后可恢复 |
| Android 桌面内测 | macOS/Windows、少量明确支持的官方 App 版本和设备，导出清单、断点、逐文件验证 | 多个家庭和不同设备能独立完成，故障可诊断，来源没有误操作 |
| 扩展覆盖 | 优先加入有效的 Mac 原生路线或 Android 独立手机版；增加已验证的版本适配器 | 新路线实际减少家长操作和支持时间，而不只是增加平台列表 |
| 持续备份 | 用户主动启动的增量归档、NAS/外置盘目标 | 能可靠识别新照片；UI 路线仍明确要求可交互会话 |
| 厂家合作 | 授权相册清单和下载接口 | 当前海马账户和历史相册完整覆盖，并有可持续的接口许可与变更机制 |

可以给 Mac 原生路线与 Android 无障碍路线各分配 1–3 个工程日作为首轮验证预算；这不是保证完成时间。桌面 Beta 的排期应在验证后按兼容矩阵估算，单一成功设备不宜直接推出全机型交付承诺。

第一轮用 5–10 个愿意参与的家庭收集设备品牌、系统、海马 App/摄像头版本、照片量和最早日期，覆盖不同来源数据。重点衡量首个文件时间、全量耗时、人工点击数、失败恢复率、漏图发现方式和单用户支持时间；这样的内测规模用于发现问题，不能证明全市场兼容。

本次 535 MB 搬运耗时很短，界面流程却需要 143 批。优先优化自动等待、批量大小和恢复机制；若要明显缩短全量导出耗时，厂家接口或能直接取得照片清单的数据路线比更换 GUI 框架更关键。

**商业定位的判断。**

“毕业时一次性导出多年照片”和“每月持续备份”是两个不同需求。先验证前者是否愿意为省时与完整性付费，再验证持续备份是否值得订阅；目前没有用户规模、付费率或平台占比证据。可以从海马适配器切入，保留共享归档核心，等这一品牌的可靠性成熟后再扩展其他婴儿摄像头。

平台方案的取舍应以普通家长能否独立完成为准。若首批用户多为有电脑的 Android 家庭，桌面版能最快交付；若多数家庭只用 iPhone，Mac 官方 App 验证和厂家合作的优先级会上升，普通 iPhone 自动点击工具并不是可直接替代的路线。

发布时应明确第三方工具身份，账户登录继续发生在官方 App 内。若打包 ADB、驱动或厂家 SDK，需要按具体组件确认分发许可；Android SDK 的整体条款与其中开源组件许可有明确区分，不能把所有预编译工具笼统视为同一种可再分发许可。[Android SDK 条款](https://developer.android.com/studio/terms)

**建议决策：Android 桌面版作为首个可交付产品；Mac 官方 iPad App 作为立即验证的低摩擦路线；Android 独立手机版作为后续扩展；厂家授权接口作为长期能力。**
